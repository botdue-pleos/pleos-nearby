# 니어바이 개발일지

커밋 단위로 왜 했는지, 무엇을 했는지, 어떻게 확인했는지 적는다.

## 2026-11-08 · v0.1.0 첫 구현

### 1. 기획 보완: 이미 있는 기능을 확인하고, 빼지 않고 강점으로

**왜**: 기획서 v0.3의 D-1(사고 정차 경고)과 D-2의 급제동 자동 감지는 티맵 V2X(전방 급정거 알림 2018, 갓길 정차 알림, 사고포착알리미 2021)와 겹친다. GitHub 공개 출품작에도 근처 차끼리 정보를 나누는 앱이 3개(Pixel TMI, 길동무, 와이퍼넷) 있다. 반면 합류 예고는 상용 서비스를 찾지 못했다.

**무엇을**
- 합류 예고(A)를 대표 기능으로 앞에 둔다.
- 겹치는 기능은 빼지 않고 더 다듬는다: 주의보는 2대 규칙, 앞쪽 차 후방 주의, 정차 차량 행동요령을 차량 신호로 확인, 터널 범위 확대·재안내.
- 새로 넣은 것 셋
  1. **비상등 감사 자동 전달**: 끼어든 뒤 비상등을 짧게 켜는 한국 운전 습관을 그대로 읽는다(말하지 않아도 됨).
  2. **행동요령 차량 신호 확인**: 비상등(Light), 트렁크·문(Door)으로 비트박스 단계를 확인해 남은 것만 말한다.
  3. **터널 앞 경고 강화**: 터널 사고의 3대 이상 연쇄 추돌 비중이 44.9%(전체 35.5%)라 터널 안 주의보는 뒤 3km까지, 1km 앞에서 한 번 더.

### 2. 빌드 설정

**무엇을**: `core`(Kotlin JVM) · `server`(Ktor) · `app`(Compose) 세 모듈. 서버 판단(`NearbyHub`)을 core에 두어 앱 안에서도 그대로 돌릴 수 있게 했다.

### 3. 판정 엔진 (core)

**무엇을**
- `Protocol.kt`: 차 ↔ 서버 메시지. 자유 텍스트·차량 번호·차종·색상 칸이 없고, 시각은 서버가 받은 시각을 쓴다. 다른 차에게 가는 말엔 보낸 차 익명 ID도 없다.
- `HazardBoard.kt`: 같은 구간 또는 바로 옆 구간(200m 경계에서 갈라지는 것 방지), 30초 안, 서로 다른 차 2대 → 주의보. 5분 소멸, 지도용 건수 통계.
- `NearbyHub.kt`: 합류 예고(60초 안 합류할 차 × 합류 지점 1km 앞 본선 차), 주의보·정차 알림 퍼뜨리기(늦게 들어온 차도 받음), 감사(뒤 150m)·문제(앞 100m) 배달과 결과 회신.
- `Detectors.kt`: 급제동(1.5초 안 3.5m/s²), 정차(급제동 뒤 또는 비상등 켜고 10초), 비상등 감사(0.8~4초, 달리는 중, 깜빡이 20초 안).
- `SafetyChecklist.kt`, `Voice.kt`(낱말 규칙 + 제보 횟수 제한), `NearbyClient.kt`(차 한 대), `AnonymousIds.kt`(10분마다 교체).
- `demo/`: 시연 2편(합류, 터널)과 재생기.

**고친 것**
- 멈춘 순간 이미 비상등을 켰는데 "비상등을 켜세요"부터 말하던 것 → 멈춘 순간 상태를 먼저 반영하고 "비상등 확인했어요"로 시작.
- 신호를 낸 차가 자기 주의보를 "후방 주의"로 다시 받던 것 → 신호 낸 차는 이미 아는 것으로 처리.
- 휴게소로 천천히 세우는 B가 급제동으로 잡히던 시나리오 값 → 감속을 약 2m/s²로.

**확인**: 테스트 25개 통과. 규칙별 테스트 + 시나리오 두 편을 처음부터 끝까지 돌려 차마다 기대한 말을 들었는지 확인.

### 4. 중계 서버 (server)

**무엇을**: Ktor WebSocket `/nearby`. 익명 ID → 연결만 기억하고, 연결이 끊기면 함께 잊는다. 로그에 위치를 남기지 않는다. `NEARBY_DEMO=1`일 때만 `/demo/jump`(서버 시계 5분 앞당기기).

**확인**: 두 WebSocket 연결 사이 감사 인사 배달 테스트 1개 통과. 에뮬레이터 앱(차 B, 여러 대 시연 모드) + PC 서버 + Node 스크립트(차 A)로 합류 예고가 서버를 거쳐 오가는 것 확인.

### 5. 차량 앱 (app)

**무엇을**: 주행 화면(앞길 띠 + 알림 카드 + 말한 내용), 행동요령 확인판, 신고 도우미, 위험 지점 지도, 시연 조작판(시나리오·차 선택·말하기 버튼·여러 대 시연). 현대차 CI 색(야간 Hyundai Blue, 위험 Active Red, 정보 Active Blue)과 Asta Sans.

**고친 것**: 재생기 상태가 Compose 상태가 아니라 화면이 안 바뀌던 것 → 바뀐 횟수(version)를 넘겨 알림 목록을 다시 읽게 함. 위험 알림이 아니면 가장 최근 알림을 크게 보이게.

**확인**: Pleos 앱 창 크기(920×1414, density 240)로 맞춘 에뮬레이터에서 장면 9개 캡처(`docs/screens`).

## 2026-11-09 · 구조도를 diagrams.net 그림으로

**왜**: 집중잔량·오래운전과 같은 방식으로 README 구조도를 맞추려고.

**무엇을**: mermaid 흐름도를 `docs/architecture.drawio`(원본)와 `docs/architecture.png`(README용)로 교체. 위는 차 한 대(차량 입력 → 신호 공급원 → core 판정 → 화면 → TTS), 아래는 중계 서버(연결표 → NearbyHub → 합류 예고·HazardBoard·정차 알림·감사/문제 배달)이고, 둘 사이를 "익명 ID · 도로 구간 · 정해진 문구"로 잇는다.

**확인**: diagrams.net 뷰어로 그려 화살표가 상자를 가로지르지 않는지, 글자가 상자 밖으로 넘치지 않는지 보고 고침.

## 2026-11-09 · 디자인: 앞길 램프

**왜**: 집중잔량·오래운전·니어바이 세 앱이 같은 남색·모래색·픽셀 칸이라 구분이 안 됐다. 현대차 광고를 바탕으로 앱마다 다른 장면을 하나씩 잡았고, 니어바이는 아이오닉 램프 캠페인 "Pixel by Pixel"(픽셀 하나는 깜빡일 뿐, 모이면 더 큰 것)을 그대로 옮겼다.

**무엇을**
- 앞길 띠 → 앞길 램프: 한 줄에 네모 픽셀 3칸, 20줄(앞 3km·뒤 1km). 꺼진 칸은 어두운 남색, 터널 칸은 테두리만.
- 새 알림이 오면 내 줄에서 그 지점까지 0.9초 동안 픽셀이 차례로 켜졌다 꺼진다(이 앱의 유일한 움직임).
- 알림 카드·행동요령·신고 도우미 제목: 빨간 바탕·빨간 글자 대신 픽셀 세 칸 + 보조색 글자(남색 바탕 위 빨간 글자는 대비가 약했다).

**확인**: 테스트 26개 통과, 에뮬레이터 화면 10장 다시 찍음(`docs/screens`).
